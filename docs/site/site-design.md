## 1. 원칙

- 문서형 레이아웃. 글 중심의 가독성을 우선합니다(C-3).
- 모바일 기준으로 설계하고 넓은 화면에서 확장합니다.
- 라이트 모드와 다크 모드를 같은 수준으로 설계합니다. 색을 반전하지 않고 모드별 값을 따로 둡니다.
- 장식 요소와 모션은 최소화합니다. 읽기 전용 사이트이며 입력 UI는 검색에 한정합니다.
- 상태와 의미를 색만으로 전달하지 않습니다. 텍스트나 모양을 함께 씁니다.

## 2. 정보 구조

| 페이지 | 경로 | 시나리오 | 구성 |
|---|---|---|---|
| 홈 | `/` | 진입 | 최근 질문 목록, 카테고리별 질문 수 |
| 카테고리 | `/category/{slug}` | SC-3 | 질문 목록(최신순), 질문별 답변 수 |
| 질문 상세 | `/q/{number}` | SC-2 | 질문 본문, 답변 목록, 원본 Discussion 링크 |
| 작성자 | `/author/{login}` | SC-1 | 답변 목록(질문 제목과 답변 본문) |
| 검색 | `/search?q=` | FR-3 | 입력창, 결과 목록(질문 제목, 일치 부분 발췌) |
| 404 | 없는 경로 | | 안내 문구, 홈 링크 |

- 카테고리 slug는 영문 고정 표기를 씁니다(예: `network`). 대응표는 도메인의 `CategoryExtractor`가 소유합니다.
- 페이지마다 `<title>`은 `{페이지 제목} · CS한잔` 형식입니다.

## 3. 브레이크포인트와 레이아웃

| 구간 | 폭 | 레이아웃 |
|---|---|---|
| 모바일 | 0~767px | 단일 컬럼. 상단 바에 메뉴 버튼, 사이트명, 검색 버튼, 테마 버튼 |
| 태블릿 | 768~1023px | 단일 컬럼. 상단 바에 검색 입력창 노출. 사이드바는 메뉴 버튼으로 열림 |
| 데스크톱 | 1024~1439px | 좌측 사이드바(256px 고정) + 본문(최대 720px). 사이드바와 본문을 묶은 틀(최대 1072px)을 가운데 정렬 |
| 넓은 데스크톱 | 1440px 이상 | 홈, 카테고리, 작성자는 위와 같은 틀을 가운데 정렬. 질문 상세만 본문 최대 1200px로 넓히고 답변을 2열로 배치 |

헤더와 하단도 같은 틀 폭을 써서 사이트명이 사이드바와 같은 선에 옵니다(`--frame-max`).

- 기준 폭 검증: 320, 375, 768, 1024, 1440px.
- 페이지 좌우 여백: 모바일 16px, 태블릿 24px, 데스크톱 32px.
- 본문 문단의 최대 폭은 데스크톱 기준 720px입니다. 2열 배치는 질문 상세의 답변 영역에만 적용합니다.

### 2열 기준을 1440px로 정한 근거

사이드바 256px, 좌우 여백, 간격을 빼면 각 열의 폭은 아래와 같습니다. 16px 본문에서 한 줄에 들어가는 한글 글자 수를 기준으로 판단했습니다.

| 화면 폭 | 열 폭 | 한 줄 한글 글자 수(추정) | 판단 |
|---|---|---|---|
| 1024px | 324px | 약 17자 | 너무 좁음 |
| 1280px | 452px | 약 25자 | 좁음. 코드블록 가로 스크롤 빈번 |
| 1440px | 532px | 약 30자 | 채택 |

본문 최대 폭을 1200px로 제한해 화면이 더 넓어져도 한 줄 길이가 계속 늘어나지 않게 합니다.

## 4. 공통 레이아웃

```
모바일 (<768)                      데스크톱 (≥1024)
┌──────────────────────┐          ┌──────────┬───────────────────────────┐
│ ☰  CS한잔     🔍  ◐  │          │ CS한잔    │            [검색…]     ◐  │
├──────────────────────┤          ├──────────┼───────────────────────────┤
│ 본문                  │          │ 카테고리  │ 본문                       │
│                      │          │ 작성자    │                           │
├──────────────────────┤          │          │                           │
│ 하단                  │          │          │ 하단                       │
└──────────────────────┘          └──────────┴───────────────────────────┘
```

| 영역 | 내용 |
|---|---|
| 본문 바로가기 | 페이지 첫 요소. 포커스를 받으면 보임 |
| 상단 바 | 사이트명(홈 링크), 검색, 테마 전환. 모바일과 태블릿은 메뉴 버튼 추가. 스크롤 시 상단 고정 |
| 사이드바 | "카테고리" 목록(이름과 질문 수), "작성자" 목록(아바타, login, 답변 수). 현재 페이지 항목 강조. 모바일 메뉴도 같은 내용 |
| 모바일 메뉴 | 사이드바와 같은 내용을 네이티브 `<dialog>`로 표시. 열면 첫 링크로 포커스, Esc와 닫기 버튼으로 닫힘, 닫으면 메뉴 버튼으로 포커스 복귀 |
| 하단 | 원본 Discussions 링크, 저장소 링크, 마지막 갱신 시각 |

- 사이드바의 현재 항목은 `aria-current="page"`, 굵은 글씨, 배경색, 왼쪽 막대를 함께 씁니다.
- 사이드바는 데스크톱에서 화면 높이에 고정되고 내용이 넘치면 사이드바 내부만 스크롤합니다.

## 5. 페이지 구성

### 5.1 홈

- h1: `CS한잔`과 한 줄 소개
- 최근 질문 목록(표시 건수는 미결정, 13장)
- 모바일에서는 목록 위에 카테고리 칩 목록을 둡니다. 데스크톱은 사이드바가 같은 역할을 하므로 생략합니다.

### 5.2 카테고리

- h1: 카테고리 이름과 질문 수
- 질문 목록, 최신순

### 5.3 질문 상세

- 상단: 카테고리 배지, 날짜, 마감 여부 라벨, h1 질문 제목, 질문 본문, "Discussions에서 보기" 링크
- 답변 영역 제목: `답변 N`(h2)
- 답변 배치:

| 조건 | 배치 |
|---|---|
| 1440px 미만 | 세로 나열. 모든 답변을 펼친 상태로 표시 |
| 1440px 이상, 답변 2건 이상 | 2열 그리드. 같은 행의 두 카드는 긴 답변의 높이에 맞춰 늘어남 |
| 1440px 이상, 답변 1건 | 단일 열. 폭은 720px |
| 답변 0건 | "아직 답변이 없습니다" 안내와 Discussions 링크 |

- 답변 순서는 작성 시각 오름차순입니다. 2열에서도 DOM 순서는 같으므로 시각 순서(왼쪽에서 오른쪽, 위에서 아래)와 스크린 리더 및 키보드 순서가 일치합니다.
- 답변 수가 홀수면 마지막 카드는 왼쪽 열에 둡니다. 두 열로 늘이지 않습니다(한 줄 길이 유지).
- 카드 안의 긴 코드블록과 표는 카드 내부에서만 가로 스크롤합니다.

#### 열린 화면의 변경 반영(새 답변, 수정, 삭제)

| 항목 | 동작 |
|---|---|
| 확인 주기 | 페이지가 보이는 동안 15초마다 새 답변 확인. 탭이 가려지면 멈추고 다시 보이면 즉시 1회 확인 |
| 갱신 범위 | 답변 목록 영역만 다시 그림. 질문 본문은 그대로. 최신 목록과 비교해 추가, 수정, 삭제를 모두 반영 |
| 추가 위치 | 목록 끝(작성 시각 오름차순 유지). 2열에서는 다음 빈칸 |
| 스크롤 | 위치를 옮기지 않음. 화면 위쪽 내용이 밀려나지 않음 |
| 알림 | `답변 N` 제목의 숫자 갱신과 "새 답변", "수정됨" 라벨로 표시. 스크린 리더 알림(`aria-live`)은 두지 않음(S4에서 요구사항 제공자 요청으로 제거) |
| 표시 | 새 카드에 "새 답변", 새 답글에 "새 답글", 본문이 바뀐 항목에 "수정됨" 텍스트 라벨. 다음 변경 반영 또는 새로고침 시 제거. 색만으로 구분하지 않음 |
| 수정 | 본문을 최신 내용으로 바꾸고 "수정됨" 라벨. 카드 순서는 유지 |
| 삭제 | 카드(답글 포함)를 제거하고 알림. 지워진 카드가 화면 안에 있었다면 아래 내용이 올라오는 것은 피할 수 없음 |
| 스크롤 | 화면 위쪽(이미 지나간 카드)의 추가, 수정, 삭제로는 보던 카드가 밀리지 않음. 브라우저 스크롤 고정(scroll anchoring)에 의존하며 Chrome에서 확인(카드 위치 446 → 447px) |
| 실패 | 표시하지 않고 다음 주기에 재시도. 3회 연속 실패 시 목록 아래에 "새 답변을 불러오지 못했습니다. 새로고침해 주세요" |
| JS 꺼짐 | 서버가 그린 목록만 표시. 새로고침으로 반영 |

### 5.4 작성자

- 머리: 큰 아바타, h1 login, "답변 N개", GitHub 프로필 링크
- 답변 블록 목록. 블록마다 카테고리 배지, 작성 시각, 질문 문장(질문 상세 링크), 답변 본문
- 최신순. 답변(최상위 댓글)만 모으고 답글은 질문 상세에서 봅니다
- 탈퇴 계정은 작성자 페이지가 없습니다. 없는 login은 404, 대소문자는 구분하지 않습니다

### 5.5 검색

- h1: `검색`
- 입력창(`type="search"`, 보이는 라벨 "질문과 답변 검색"), 결과 건수, 결과 목록
- 결과 항목: 질문 문장 링크(일치한 글자는 제목 안에서 `<mark>`로 강조), 답변에서 일치한 경우 "답변 · 작성자"와 일치 주변 발췌(질문당 최대 3개)
- 순서: 질문 문장에서 일치한 질문 먼저, 그다음 일치 횟수가 많은 순, 같으면 최신순
- 검색어는 대소문자, 앞뒤 공백, 줄바꿈 차이를 무시하고 부분 문자열로 비교(조사가 붙은 "캐시는"도 "캐시"로 찾음). 최대 100자
- 헤더: 768px 이상은 검색 입력창, 미만은 검색 버튼(검색 페이지로 이동)
- 검색은 서버에서 수행합니다. 입력창은 `GET /search?q=` 폼이라 JS가 꺼져도 동작합니다.
- 입력하는 대로 결과가 바뀌는 검색은 S4 범위에서 뺐습니다(제출 방식만). 주소의 `q`로 결과를 공유할 수 있습니다.

| 검색어 강조 | 12.57 | 8.07 |

- 보조 텍스트를 강조 배경 위에 두면 다크에서 4.04로 기준 미달입니다. S1의 렌더링 측정에서 발견했고, 강조 배경 위 숫자와 메타 정보는 `--color-badge-fg`를 씁니다.
- 테두리 대비(라이트 1.18, 다크 1.72)는 3:1에 못 미칩니다. 테두리는 장식으로만 쓰고, 카드 구분은 간격과 배경색 차이로도 전달합니다.
- 구현 후 실제 렌더링에서 자동 점검 도구로 다시 확인합니다.

## 7. 테마 전환

| 항목 | 동작 |
|---|---|
| 기본값 | 시스템 설정(`prefers-color-scheme`) |
| 전환 버튼 | 상단 바. 누를 때마다 라이트 ⇄ 다크. 라이트에서는 달, 다크에서는 해 아이콘(누르면 바뀔 모드). 아이콘은 CSS가 고르므로 JS 실행 전에도 맞게 보임. 이름은 "다크 모드로 전환" 또는 "라이트 모드로 전환" |
| 시스템 설정 | 저장된 선택이 없으면 OS 설정을 따르고 OS 설정이 바뀌면 함께 바뀜. 버튼을 누른 뒤에는 선택한 테마로 고정(시스템 단계로 돌아가는 버튼은 두지 않음) |
| 저장 | `localStorage`. 접근 실패 시 시스템 설정으로 동작 |
| 깜빡임 방지 | `<head>`의 인라인 스크립트가 첫 렌더링 전에 `data-theme`을 지정 |
| JS 꺼짐 | 시스템 설정만 적용. 전환 버튼은 숨김 |
| 기타 | `color-scheme` 속성을 모드에 맞춰 지정해 스크롤바와 입력창도 함께 전환 |

## 8. 컴포넌트

| 컴포넌트 | 구성 | 사용 페이지 |
|---|---|---|
| 질문 항목 | 카테고리 배지, 날짜, 제목 링크, 답변 수, 마감 라벨 | 홈, 카테고리 |
| 답변 카드 | 작성자(작성자 페이지 링크), 작성 시각(`<time>`), 본문, 새 답변 라벨(해당 시) | 질문 상세 |
| 답변 목록 | 서버가 그린 목록에 폴링 결과를 이어 붙이는 클라이언트 컴포넌트. 5.3 "새 답변 반영" | 질문 상세 |
| 답변 블록 | 카테고리 배지, 작성 시각, 질문 문장 링크, 본문 | 작성자 |
| 카테고리 배지 | 텍스트 배지. 색으로 카테고리를 구분하지 않음 | 질문 항목, 질문 상세 |
| 마감 라벨 | "마감" 텍스트 배지. 진행 중인 질문은 "진행 중" | 질문 항목, 질문 상세 |
| 검색 결과 항목 | 질문 제목 링크, `<mark>` 강조 발췌 | 검색 |
| 본문 영역 | GitHub `bodyHTML`을 살균 후 출력. 아래 규칙 적용 | 질문 상세, 작성자 |
| 테마 버튼 | 아이콘 버튼과 접근 가능한 이름 | 상단 바 |
| 아바타 | 원형, 이름 글자 크기의 1.6배(`em`). 이미지는 장식(`alt=""`)으로 두어 이름을 두 번 읽지 않음. 이미지가 없으면 이니셜, 탈퇴 계정은 사람 모양. GitHub 이미지 서버의 https 주소만 사용 | 답변 카드, 답글, 사이드바, 작성자 페이지(3.5배) |
| 메뉴 버튼 | `aria-expanded`, `aria-controls` | 상단 바(1024px 미만) |

본문 영역 규칙:

| 요소 | 처리 |
|---|---|
| 코드블록 | `--color-code-bg`, 내부 가로 스크롤, 넘치는 쪽 가장자리 그림자로 스크롤 단서 표시, 복사 버튼 없음(MVP). 문법 강조 색은 MVP에서 제외 |
| 표 | 가로 스크롤과 가장자리 그림자. 칸은 단어 단위로만 줄 바꿈(전역 `overflow-wrap: anywhere` 예외) |
| 이미지 | `max-inline-size: 100%`, `height: auto`, 작성자가 쓴 대체 텍스트 유지 |
| 링크 | 밑줄 유지 |
| 이모지 | 원문 그대로 |
| 줄바꿈 | 원본의 `\r\n`은 데이터 정규화 단계에서 처리 |

아이콘은 SVG 한 세트(Lucide)만 씁니다. 이모지를 아이콘으로 쓰지 않습니다. 장식용 아이콘은 `aria-hidden="true"`입니다.

## 10. 수용 기준

`better-interface`의 즉시 HIGH 판정 기준 중 이 사이트에 해당하는 항목입니다. 하나라도 걸리면 머지하지 않습니다.

| 기준 | 이 사이트에서 확인할 곳 |
|---|---|
| 접근 가능한 이름이 없는 상호작용 요소 | 메뉴 버튼, 테마 버튼, 모바일 검색 버튼 |
| 보이는 포커스 표시가 없는 요소 | 모든 링크, 버튼, 입력창. `outline: 2px solid var(--color-focus); outline-offset: 2px` |
| 포인터로만 닿는 요소 | 모바일 메뉴, 테마 전환, 검색 |
| `prefers-reduced-motion` 무시 | 전환 효과 |
| 320px 폭 또는 200% 확대에서 잘리거나 겹치는 요소 | 상단 바, 질문 항목, 답변 카드 |
| 대비 미달 텍스트 | 6.2의 모든 조합, 라이트와 다크 |
| 색만으로 전달하는 상태 | 마감 여부, 현재 사이드바 항목, 검색어 강조 |
| 전체 내용에 접근할 수 없는 잘린 텍스트 | 질문 제목 말줄임 금지 |
| 단서 없이 스크롤 끝 너머에 있는 내용 | 코드블록과 표의 가로 스크롤 |

추가 기준:

- 페이지당 h1 하나, 제목 단계 순서 유지
- 키보드만으로 홈 → 카테고리 → 질문 상세 → 작성자 이동과 검색 가능
- 랜드마크: `header`, `nav`(사이드바, 라벨 "사이트 메뉴"), `main`, `footer`

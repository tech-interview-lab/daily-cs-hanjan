# ADR-0001 렌더링 방식 선택

| 항목 | 내용 |
|---|---|
| 상태 | 보류 (실측 대기) |
| 작성일 | 2026-10-15 |
| 관련 요구사항 | FR-4, C-4, C-5 |
| 영향 범위 | `site/src/main/entrypoints`, 배포 설정. 상세는 [site-structure.md](../site/site-structure.md) 11장 |

## 1. 맥락

새 댓글은 등록 후 1분 이내 사이트에 반영되어야 합니다(FR-4). 운영 비용은 추가로 발생하지 않아야 하며(C-5), 기존 EC2 서버는 사용할 수 있습니다(C-4). 사이트는 읽기 전용이므로 쓰기 경로가 없습니다. 데이터의 원본은 GitHub Discussions입니다.

## 2. 판단 기준

| 기준 | 출처 | 확인 방법 |
|---|---|---|
| 반영 지연 | FR-4 | 4장 실측 |
| 추가 비용 | C-5 | 요금 정책 확인 |
| 운영 부담 | 장애 지점 수, 운영 대상 수 | 구성도 비교 |
| 외부 의존 위험 | 공개 프리뷰 기능 사용 여부 | 공식 문서 재확인 |

## 3. 선택지

| 안 | 반영 경로 | 장점 | 단점 및 위험 |
|---|---|---|---|
| A. 정적 사이트 + 이벤트 재빌드 | 댓글 이벤트 → Actions 빌드 → Pages 배포 | 서버 불필요. 운영 부담 낮음 | 빌드와 배포 시간이 1분을 넘을 수 있음. `discussion_comment` 트리거는 기본 브랜치의 워크플로 파일에서만 실행되며 공개 프리뷰 상태라 동작이 바뀔 수 있음 |
| B. ISR | 재검증 주기 또는 요청 시 페이지 갱신 | 정적 사이트의 속도와 갱신을 절충 | Node 호스팅 필요. 자체 호스팅 시 EC2 운영 부담 발생 |
| C. 요청 시 SSR | 요청마다 GraphQL 조회 | 항상 최신 | 요청마다 외부 API 호출. 호출 한도와 지연 발생. 토큰을 서버에 보관 |
| D. CSR | 브라우저가 직접 조회 | 서버 로직 최소 | 브라우저에 토큰 노출. 프록시를 두면 C와 동일해짐. 별도 안으로 보지 않음 |
| E. EC2 웹훅 + 증분 갱신 | 웹훅 수신 → 해당 질문만 갱신 → nginx가 정적 파일 제공 | 반영 지연 최소(수 초 예상, 미측정) | EC2 장애가 곧 사이트 장애. 웹훅 서명 검증 필요. 운영 책임 증가 |

- GraphQL 호출에는 토큰이 필요한 것으로 알려져 있으나 공식 문서에서 명시를 확인하지 못했습니다. S0에서 확인합니다.
- 안 A의 트리거 조건은 구현 전에 공식 문서로 재확인합니다.

## 4. 결정 절차

### 4.1 실측

| 항목 | 내용 |
|---|---|
| 목적 | 안 A의 반영 지연이 1분 이내인지 확인 |
| 환경 | 임시 저장소(본 저장소와 분리) |
| 측정 구간 | 댓글 `createdAt`부터 공개 URL에서 해당 댓글이 노출되는 시각까지 |
| 절차 | 1. 최소 페이지와 `discussion_comment` 트리거 워크플로 구성<br>2. 테스트 Discussion에 댓글 작성<br>3. 공개 URL을 1초 간격으로 조회해 문구 노출 시각 기록<br>4. 3회 반복 |
| 기록 | 중앙값과 최댓값 |
| 위임 후보 | 폴링 스크립트 작성. 수치는 사람이 원본 타임스탬프와 대조해 확인 |

## 6. 결과 및 영향

- 결정에 따라 바뀌는 범위는 조립 레이어(`main`)와 배포 설정으로 한정합니다. 도메인, 애플리케이션, 어댑터, 프레젠테이션 레이어는 영향을 받지 않도록 설계합니다.
- 안 E를 선택하면 `ArchiveWriter`의 증분 갱신(`upsertQuestion`)을 사용합니다. 포트 정의에는 처음부터 포함합니다.

# ADR-0002 마감 댓글 식별 방식

| 항목 | 내용 |
|---|---|
| 상태 | 확정 (2026-10-15) |
| 작성일 | 2026-10-15 |
| 관련 요구사항 | C-1, FR-2, FR-4 |
| 영향 범위 | `site/src/domain/policies`, n8n 워크플로의 "Add Closing Comment" 노드 |

## 1. 맥락

질문 생성 파이프라인은 이전 질문을 닫을 때 마감 안내 댓글을 자동으로 등록합니다. 본문은 `🔒 다음 질문이 올라와서 이 토론은 마감되었습니다.`로 시작합니다. 이 댓글은 답변이 아니므로 사이트 반영 대상에서 제외해야 합니다(C-1). 제외하지 않으면 작성자별 답변 수(FR-2)와 질문별 답변 수가 어긋납니다.

## 2. 선택지

| 안 | 방식 | 평가 |
|---|---|---|
| 1 | 작성 계정으로 구분 | 자동 댓글이 본인 계정으로 등록되므로 구분 불가 (확인 완료) |
| 2 | 질문의 마지막 댓글을 마감 댓글로 간주 | 닫힌 뒤 늦은 답변이 달리면 오판 |
| 3 | 숨은 표식과 고정 문구 병행 (채택) | 표식 도입 전 댓글도 처리 가능. 문구가 바뀌면 식별 실패 위험 |

## 3. 식별 규칙

| 대상 | 식별 규칙 |
|---|---|
| 표식 도입 이후 댓글 | 본문에 `<!-- hanjan:auto-close -->` 포함 |
| 표식 도입 이전 댓글 | 본문이 고정 문구 `🔒 다음 질문이 올라와서`로 시작 |

- 판정 로직은 도메인 레이어의 `AutoClosePolicy`에 둡니다. 외부 입출력 없이 문자열만 검사하므로 단위 테스트가 가능합니다.
- 표식 추가는 n8n의 "Add Closing Comment" 노드 본문 수정으로 반영하며 별도 작업으로 진행합니다. 수정 후 워크플로 백업(`n8n/daily-question-workflow.json`)도 갱신합니다.

## 4. 위험

| 위험 | 대응 |
|---|---|
| 마감 문구 변경 시 식별 실패 | 문구 변경 시 정책 코드와 테스트를 함께 수정. 표식 도입 후에는 표식이 우선 |
| 사용자 댓글이 고정 문구로 시작 | 발생 가능성 낮음. S0 추출 결과에서 오탐 여부 확인 |

## 5. 검증

| 항목 | 기준 |
|---|---|
| 질문당 제외 건수 | 2건 이상인 질문 없음 |
| 전체 제외 건수 | 닫힌 질문 수 이하 |
| 반영 댓글 수 | 전체 댓글 수에서 제외 건수를 뺀 값과 일치 |

## 6. 결정

| 항목 | 내용 |
|---|---|
| 결정 | 숨은 표식과 고정 문구 병행 (AI 제안 수락) |
| 결정일 | 2026-10-15 |
| 근거 | 자동 댓글이 본인 계정으로 등록되어 작성 계정으로 구분할 수 없음. 위치 기반 판정은 늦은 답변에서 오판 |

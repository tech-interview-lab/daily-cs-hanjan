# AI 활용 기록

CS한잔 사이트를 만들면서 AI를 어떻게 쓰는지 정리한 문서입니다. 

작업 전에 정한 규칙과 작업하면서 쌓는 기록이 함께 들어 있고 실제로 한 것만 적습니다.

관련 이슈: #(번호)

## 왜 검증에 무게를 두는가

AI 도구를 쓰는 개발자는 늘었지만 정확도를 믿는 비율은 29%에 그칩니다. 

거의 맞지만 틀린 코드를 고치느라 시간이 더 든다는 응답은 66%에 달합니다([Stack Overflow 2025 설문](https://stackoverflow.blog/2025/12/29/developers-remain-willing-but-reluctant-to-use-ai-the-2025-developer-survey-results-are-here/)). 코드를 빨리 만드는 것보다 맞는지 확인하는 데 시간을 씁니다.

## 원칙

AI가 쓴 코드는 내 말로 설명할 수 있을 때만 머지합니다. 

구현에 앞서 확인 방법부터 정하고 결정은 사람이 내립니다. AI는 선택지와 초안을 제시하며 틀린 경우도 기록으로 남깁니다.

## 1. 스펙 작성

산출물은 `site-spec.md`입니다.

- 입력은 이슈 본문과 MVP 범위(카테고리별 열람, 작성자별 모아보기, 검색)입니다.
- AI에게는 구현하지 말고 질문만 하도록 지시합니다.
- 질문은 나눠서 받습니다. 이번에는 두 번 진행했습니다. 1회차는 사용 장면, 스택 방향, 디자인 톤을 묻고, 2회차는 반영 지연 허용치와 서버 사용 여부를 물었습니다.
- 결정마다 출처를 표시합니다. 내가 정함, AI 제안을 받아들임, AI 제안을 기각함 중 하나입니다.
- 기능마다 확인 방법을 한 줄씩 적고, AI 제안의 처리 결과(수락과 기각 건수)를 남깁니다. 기각이 없으면 0건으로 기록합니다. 이번 스펙은 AI 제안 3건을 모두 수락했습니다(`site-spec.md` 7장).

## 2. 슬라이스 구현

기능을 작게 나눠 하나씩 확인하며 쌓습니다.

| 슬라이스 | 내용 | 확인 방법 |
|---|---|---|
| S0 | Discussions를 JSON으로 추출 | 질문 수가 GitHub 목록과 같습니다 |
| S1 | 카테고리별 목록 페이지 | 카테고리마다 페이지가 생기고 질문 수가 맞습니다 |
| S2 | 질문 상세(답변, 작성자), 웹훅 재검증, 새 답변 폴링 | 댓글 수와 대댓글 수가 원본과 같습니다. 작성자가 null인 댓글(탈퇴한 계정)에서도 깨지지 않습니다. 테스트 댓글이 1분 이내 반영되고, 열린 화면에는 폴링 주기 안에 추가됩니다 |
| S3 | 작성자별 페이지 | 작성자별 답변 수의 합이 전체 답변 수와 같습니다 |
| S4 | 검색 | 질문 제목 키워드와 답변 본문 키워드로 각각 검색됩니다 |

슬라이스마다 순서는 같습니다. 확인 방법 적기 → AI에게 구현 맡기기 → diff를 읽고 내 말로 설명하기 → 확인 실행 → 커밋.

머지하기 전에 세 가지를 확인합니다. 설명할 수 있는지, 동작한다는 증거가 있는지, 내가 고친 곳이 있는지입니다.

자동 검증은 빌드 성공, 링크 검사, 건수 일치로 시작합니다.

## 3. CLAUDE.md와 `.claude` 구성

Claude Code 공식 문서는 CLAUDE.md를 파일당 200줄 이내로 쓰도록 권장합니다. 

길어질수록 지침 준수율이 떨어집니다([How Claude remembers your project](https://code.claude.com/docs/en/memory)).

| 구성 요소 | 담는 것 | 이 프로젝트의 적용 |
|---|---|---|
| `CLAUDE.md` | 매번 알아야 하는 사실(프로젝트 소개, 문서 지도, 명령, 금지 사항) | 작성 완료. 현재 76줄 |
| `.claude/rules/` | 특정 경로에서만 필요한 규칙. `paths:`로 범위 지정 | `site-layer-rules.md` (`site/src/**` 작업 때만 로드) |
| `.claude/skills/` | 여러 단계의 반복 절차. 평소에는 설명만 로드 | 후보: 슬라이스 구현 절차, ai-log 작성 |
| `.claude/settings.json`의 hooks | 어기면 안 되는 규칙의 강제. CLAUDE.md는 컨텍스트일 뿐 강제하지 않음 | 후보: main 직접 푸시, 강제 푸시, 비밀키 커밋, PR 승인·머지 명령 차단 |
| `.claude/agents/` | 출력이 긴 검증 작업. 별도 컨텍스트에서 실행하고 요약만 반환 | 후보: 건수 대조 `verifier` |

- 규칙은 실제로 겪은 실수에서만 추가하고, 추가 사유를 커밋 메시지에 적습니다.
- 처음부터 길게 써 달라고 AI에게 맡기지 않습니다.
- 이 파일들의 커밋 히스토리가 곧 시행착오 기록이 됩니다.

## 4. 작업 위임

검증하기 쉬운 일만 맡깁니다.

- 맡길 일: 검색 인덱스 생성, 링크·접근성 점검, 엣지케이스 샘플(빈 답변, 이모지, 긴 코드블록, 작성자 null) 작성과 테스트, 건수 대조(`verifier` 에이전트 후보)
- 맡기기 전에 입력, 출력, 완료 기준을 적습니다.
- 결과는 맡긴 방법과 다른 방법으로 확인합니다. 예를 들어 인덱스 건수를 원본 API 건수와 직접 비교합니다.
- 여러 작업을 동시에 돌릴 때는 수정하는 파일이 겹치지 않게 나눕니다.
- 맡기지 않는 일: 아키텍처 결정, 스펙 변경

## 기록 방법

작업마다 `docs/ai/logs/YYYY-MM-DD-제목.md`를 하나 만듭니다. 작성 규칙은 `ai-log-guide.md`에 있습니다.

```markdown
# 2026-10-13 제목

- 시킨 것:
- AI 결과:
- 내가 고친 것:
- 확인 방법과 결과:
- 틀렸거나 아쉬웠던 점:
```

AI를 활용한 PR은 템플릿 하단에 아래 섹션을 추가합니다.

```markdown
## AI 활용 내역

- 맡긴 것:
- 직접 확인한 것:
- AI가 틀려서 고친 것:
- 기각한 AI 제안:
```

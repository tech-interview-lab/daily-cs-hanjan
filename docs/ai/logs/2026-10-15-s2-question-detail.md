- 틀렸거나 아쉬웠던 점:
  - 없는 질문 번호가 404가 아니라 500이었음. GitHub는 없는 번호에 `data`와 `NOT_FOUND` 오류를 함께 보내는데 어댑터가 모든 오류를 실패로 처리. 테스트가 못 잡은 이유는 가짜 GitHub 서버가 실제와 다르게 오류 없이 `null`만 보냈기 때문. 가짜 서버를 실제 응답 모양으로 고쳐 테스트로 먼저 재현한 뒤 수정
  - 부분 갱신 첫 검증이 실패. 처음 추정(미리 방문하면 캐시가 채워짐)은 틀렸고, 정적 페이지는 방문해도 데이터 함수를 실행하지 않음을 확인. 실제 원인은 빌드 때 캐시가 실행 중 메모리 캐시에 없어 배포 직후 첫 재생성 때 한 번 다시 조회하는 것. 이후에는 질문 단위로 동작함을 별도 재현으로 확인하고 ADR-0001 6.1에 기록
  - 폴링 E2E의 "스크롤 위치 유지" 판정이 처음엔 `scrollY` 비교라 실패. 실제로는 브라우저가 위쪽에 늘어난 높이만큼 스크롤을 보정해 화면이 밀리지 않은 것. 판정 기준을 "보던 카드의 화면 위치"로 바꿈
  - 엣지 데이터 화면에서 표 칸이 글자 단위로 쪼개지는 문제와 코드블록·표의 가로 스크롤 단서 없음(better-interface 기준 HIGH)을 캡처로 발견. 수치 점검은 둘 다 통과했으므로 눈으로 본 확인이 필요했음
  - 웹훅 포트를 WebhookVerifier에서 WebhookReceiver로, 폴링용 ListNewAnswers 대신 GetQuestionDetail 재사용으로 설계를 바꿈(site-structure.md 7~8장)
  - 바탕화면 iCloud 동기화가 `.next` 안에 " 2", " 3" 사본을 만들어 타입 검사가 깨짐. `.next`를 지우고 진행. 소스와 `.git`에는 사본 없음
